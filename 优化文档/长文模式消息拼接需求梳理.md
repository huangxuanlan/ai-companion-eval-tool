# 长文模式消息拼接需求整理

保留多模型适配能力，聚焦**结构正确性**和**消除冗余参数/重传风险**。

## 一、当前拼接架构全景

### 1.1 两套独立路径

| 路径 | 入口 | 状态 |
|:-----|:-----|:-----|
| **生产路径** | [MessageAssembler.build_messages()](file:///E:/提效工具/长文模式生成/server/services/message_assembler.py#L138-281) | ✅ 活跃在用，支持多模型分支 |
| **批量测试路径** | [generate.py:build_messages()](file:///E:/提效工具/长文模式生成/generate.py#L270-324) | ⚠️ 架构过时（v2.1），无首轮跳过/Depth Injection/记忆上下文块 |

### 1.2 生产路径调用链

```
conversation_service.generate_interactive_turn()
  → conversation_generation.execute_single_turn()
    → build_memory_context_block(profile, moments, dialogue_summary) → memory_context 字符串
    → service._build_messages_internal(
        ..., dialogue_summary=..., memory_context=..., conversation_history=...,
      )
      → MessageAssembler.build_messages()
```

### 1.3 生产路径消息结构（当前实现，非首轮）

**千问模型**：
| 位置 | role | 内容 |
|:-----|:-----|:-----|
| [0] | system | 主 system + FEW_SHOT_PREFIX（合并） |
| [1] | user | Few-shot user 示例 |
| [2] | assistant | Few-shot assistant 示例 |
| [3] | system | SEPARATOR + STYLE_ISOLATION + memory_context（合并） |
| [4+] | user/assistant | 对话历史（含 Depth Injection） |
| [N-1] | system | Core_Constraints |
| [N] | user | `<user_input>...</user_input>` |

**Gemma 模型**：
| 位置 | role | 内容 |
|:-----|:-----|:-----|
| [0] | system | 主 system |
| [1] | system | Few-shot system 内嵌（XML 标签） |
| [2] | system | STYLE_ISOLATION（XML包裹）+ memory_context（合并） |
| [3+] | user/assistant | 对话历史（Depth Injection XML包裹） |
| [N-1] | system | Core_Constraints（`<rules>` XML包裹） |
| [N] | user | `<user_input>...</user_input>` |

**Default 模型**（豆包/Kimi/DeepSeek 等）：
| 位置 | role | 内容 |
|:-----|:-----|:-----|
| [0] | system | 主 system |
| [1] | system | Few-shot system 内嵌（纯文本） |
| [2] | system | STYLE_ISOLATION（单独） |
| [3] | system | memory_context（单独） ← **与千问/Gemma不同** |
| [4+] | user/assistant | 对话历史（含 Depth Injection） |
| [N-1] | system | Core_Constraints |
| [N] | user | `<user_input>...</user_input>` |

### P2：Default 模型 STYLE + memory 分离

**位置**：[message_assembler.py:L234-238](file:///E:/提效工具/长文模式生成/server/services/message_assembler.py#L234-238)

**现象**：default 分支（非千问、非 Gemma）将 `STYLE_ISOLATION` 和 [memory_context](file:///E:/%E6%8F%90%E6%95%88%E5%B7%A5%E5%85%B7/%E9%95%BF%E6%96%87%E6%A8%A1%E5%BC%8F%E7%94%9F%E6%88%90/server/services/conversation_generation.py#102-120) 作为两条独立 system 消息：

## 三、保留的多模型适配能力

以下模型特定逻辑**应保留**，不做一刀切统一：

| 适配项 | 涉及模型 | 原因 |
|:------|:---------|:-----|
| Few-shot 注入方式 | 千问 → user/assistant 角色注入；其他 → system 内嵌 | 千问对 user/assistant 角色信号更敏感，其他模型的 Plan B 避免 RSO |
| XML 标签包裹 | Gemma → Style/Depth/Core 用 XML | Gemma 4 对 XML 闭合标签遵循度最高 |
| 中间 system 块合并策略 | 千问含 SEPARATOR；Gemma 不含 SEPARATOR 但有 XML 包裹 | 模型对上下文边界感知方式不同 |
| Depth Injection 格式 | Gemma → `<system_reminder>` 包裹 | 模型特定的注意力窗口策略 |
| Core Constraints 格式 | Gemma → `<rules>` 包裹 | 同上 |
