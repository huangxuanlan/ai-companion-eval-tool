# 多模型并行上限放开 — 开发计划

## 目标

将模型对比/A·B 测试/批量测试的并行模型数从硬编码 3 放开为可配置（默认 10），同时增加 Provider 限流风险提示。

## 调研发现

| 项目 | 现状 |
|------|------|
| 后端全局并发上限 | `MAX_CONCURRENT_CONVERSATIONS = 24`（config.py L194），**已足够** |
| 3 模型硬编码 | 3 处：models.py L56、chat.py L58、conversations.py L667 |
| 可用模型总数 | 17 个 BUILTIN（含 1 个 deprecated） |
| Provider 分布 | DashScope×5、Volcengine×5、Google×3、MiniMax×2、Moonshot×1、Local×1 |

### 风险评估

| Provider | 同时最多几个模型 | RPM 限制 | 风险等级 |
|----------|---------------|---------|---------|
| DashScope（阿里云）| 5 | ~2000 RPM | ⚠️ 中（5 路并发可扛） |
| Volcengine（火山）| 5 | ~2000 RPM | ⚠️ 中 |
| Google Gemini | 3 | 免费 15 RPM | 🔴 高（3 路并发 + 打分可能超限） |
| MiniMax | 2 | ~500 RPM | 🟢 低 |
| Moonshot | 1 | ~500 RPM | 🟢 低 |

**结论**：放开到 10 模型并行是安全的，核心风险集中在 Google Gemini（3 个模型共用 15 RPM 免费额度）。引擎层已有 `call_with_retry` 重试兜底，加上 Sprint 2 的 3 次自动重试，429 可自动恢复。

### 4. 前端 Provider 限流警告

#### [MODIFY] [legacy_bundle.js](file:///e:/提效工具/长文模式生成/server/static/js/legacy_bundle.js)

在模型多选 UI 的 `onchange` 回调中，按 Provider 聚合检查：

```javascript
function checkProviderConflicts(selectedModelIds) {
  // 从 /api/models 缓存中按 provider 分组
  const providerGroups = {};
  selectedModelIds.forEach(id => {
    const model = cachedModels.find(m => m.id === id);
    if (model) {
      const p = model.provider;
      providerGroups[p] = (providerGroups[p] || []);
      providerGroups[p].push(model.display_name);
    }
  });
  
  const warnings = [];
  for (const [provider, models] of Object.entries(providerGroups)) {
    if (models.length >= 3) {
      warnings.push(`⚠️ ${models.length} 个模型共用 ${provider} API，可能触发限流`);
    }
  }
  return warnings;
}
```

在模型选择区域下方显示警告 badge（黄色背景）。
